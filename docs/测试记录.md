## 4. 白盒检查点

### 4.1 借书事务

`BorrowServiceImpl.add()` 使用 `@Transactional`，执行顺序：

1. 校验用户与图书是否存在
2. 校验库存是否大于 0
3. 校验收否存在未归还的重复记录
4. 执行 `update book set stock = stock - 1 where id = ? and stock > 0`
5. 插入借阅记录

库存扣减条件中带有 `stock > 0`，可以避免并发请求把库存扣成负数。

### 4.2 还书事务

1. 查询借阅记录
2. 已归还则拒绝重复操作
3. 校验归还时间不早于借阅时间
4. 更新 `return_time`
5. 执行 `stock = stock + 1`

上述步骤在同一个事务中，出现异常会回滚。

### 4.3 删除借阅记录

- 删除已归还记录：不改库存
- 删除未归还记录：补回库存
- 整个方法使用 `@Transactional`

### 4.4 权限拦截

- `AuthInterceptor` 校验 `Authorization: Bearer <token>`
- 登录、注册、登出、健康检查被排除
- `AuthUtil.requireAdmin()` 控制管理员操作
- `AuthUtil.requireSelfOrAdmin()` 控制借阅记录的归属访问

### 4.5 统一异常处理

`GlobalExceptionHandler` 将业务异常、唯一约束冲突和其他异常统一转换成：

```json
{
  "code": 500,
  "msg": "错误提示",
  "data": null
}
```

## 5. CORS 测试说明

预检请求返回：

```text
HTTP/1.1 200
Access-Control-Allow-Origin: http://127.0.0.1:5173
Access-Control-Allow-Methods: GET,POST,PUT,DELETE,OPTIONS
```

项目使用 `allowedOriginPatterns("*")`，因此响应头回显请求来源，而不是返回字面量 `*`。
这属于正常行为，浏览器可以正常完成跨域请求，页面已实际完成登录和数据加载。
